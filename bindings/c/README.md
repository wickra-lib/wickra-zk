# wickra-zk C ABI

The hub every C-capable language links against: C, C++, C#, Go, Java and R all
reach wickra-zk through this library rather than through their own bindings to
Rust.

## Surface

Four entry points, and no proof crosses the boundary by value:

```c
WickraZk *wickra_zk_new(void);
void      wickra_zk_free(WickraZk *handle);
int32_t   wickra_zk_command(WickraZk *handle, const char *cmd_json,
                            char *out, uintptr_t cap);
const char *wickra_zk_version(void);
```

The handle is opaque and the payloads are always UTF-8 JSON. That is deliberate:
a proof carries a receipt, a journal and an image id, and marshalling those
through six foreign type systems is six chances to disagree about a byte. One
JSON boundary is one place to be right.

## The two-call idiom

`wickra_zk_command` writes into a buffer you own, so you never free memory the
library allocated:

```c
WickraZk *h = wickra_zk_new();
const char *cmd = "{\"cmd\":\"version\"}";

int32_t len = wickra_zk_command(h, cmd, NULL, 0);   /* how long? */
char *buf = malloc((size_t)len + 1);
wickra_zk_command(h, cmd, buf, (size_t)len + 1);    /* now write it */

puts(buf);
free(buf);
wickra_zk_free(h);
```

A buffer that is already large enough needs only one call: whenever the response
fits, it is written immediately.

## Return values

A **non-negative** return is the response length in bytes, excluding the
terminating NUL. A **negative** return is an ABI-level failure:

| | |
|---|---|
| `WICKRA_ZK_ERR_NULL` (-1) | a required pointer was null |
| `WICKRA_ZK_ERR_UTF8` (-2) | `cmd_json` was not valid UTF-8 |
| `WICKRA_ZK_ERR_PANIC` (-3) | a panic was caught at the boundary |

Domain errors are **not** negative. A malformed spec or a receipt that does not
verify is an answer, not a transport failure, and arrives in the buffer as
`{"ok":false,"error":...}` — the same contract every other binding sees.

The panic code matters more here than in most C ABIs: proving runs a zkVM, and a
panic unwinding across an FFI boundary is undefined behaviour. It is caught and
reported rather than allowed to take the caller's process with it.

## C++

`wickra_zk.hpp` is an optional header-only layer: a move-only RAII owner for the
handle and a `std::string` round trip that grows its buffer once, using the
length the C ABI reports.

```cpp
#include "wickra_zk.hpp"

wickra_zk::Prover p;
auto out = p.command(R"({"cmd":"version"})");
```

## Building

```sh
cargo build -p wickra-zk-c --release
```

Produces a `cdylib` and a `staticlib`. The header is generated by cbindgen and
committed; `cargo run --bin regen-header` is not a thing here — regenerate with
`cbindgen --config cbindgen.toml --output include/wickra_zk.h .` from this
directory, and CI checks the committed copy for drift.
